A evolução: AWT → Swing → JavaFX

BibliotecaComo desenhaMarca registrada
AWT (1995)Usa componentes nativos do sistema operacionalChamados heavyweight. Mudam de aparência conforme o SO
Swing (1998)Desenha tudo em Java, por cima do AWTLightweight. Classes começam com J. Tem Look and Feel trocável
JavaFX (2008)Grafo de cena, com aceleração gráficaSepara layout (FXML) de estilo (CSS) e de lógica (controller)
Pegadinha clássica Swing não substituiu o AWT — ele foi construído em cima dele. Por isso o ActionListener, que você usa em Swing, vem de java.awt.event. Se a alternativa disser "Swing eliminou completamente o AWT", está errada.

Os dois erros mais cobrados
  • ButtonGroup: sem ele, os JRadioButton podem ser marcados todos juntos. É o ButtonGroup — e não o painel — que faz a exclusividade. Ele agrupa logicamente, não visualmente: não aparece na tela.
  • JScrollPane: JTextArea e JTable não rolam sozinhos. Você adiciona o componente ao scroll, e o scroll ao painel: painel.add(new JScrollPane(tabela)).

Frames — JFrame tema do 02 | 06

public class Janela extends JFrame {
    public Janela() {
        setTitle("Cadastro de Pessoa");      // texto da barra de título
        setSize(400, 300);                   // largura x altura em pixels
        setDefaultCloseOperation(EXIT_ON_CLOSE); // fecha o programa junto com a janela
        setLocationRelativeTo(null);           // centraliza na tela
        setVisible(true);                     // SEMPRE por último
    }
}
Duas pegadinhas de JFrame
  • setVisible(true) vem por último. Componente adicionado depois disso pode não aparecer até a janela ser redesenhada.
  • Sem setDefaultCloseOperation(EXIT_ON_CLOSE) o padrão é apenas esconder a janela (HIDE_ON_CLOSE) — o programa continua rodando em segundo plano.

Decore estes dois padrões JFrame nasce com BorderLayout; JPanel nasce com FlowLayout. E no BorderLayout, se você adicionar dois componentes na mesma região, o segundo substitui o primeiro — o primeiro some.

Eventos — o clique do botão

Este é o coração do bloco. Um evento em Swing tem sempre três peças: a fonte (o botão), o ouvinte (ActionListener) e o objeto de evento (ActionEvent).

botaoSalvar.addActionListener(new ActionListener() {
    public void actionPerformed(ActionEvent e) {
        String nome = campoNome.getText();
        JOptionPane.showMessageDialog(null, "Salvo: " + nome);
    }
});

// forma curta, com expressão lambda (Java 8+)
botaoSalvar.addActionListener(e -> salvar());
O erro que mais aparece em "ache o erro" Criar o listener e esquecer de registrar no componente. Escrever o método actionPerformed não faz nada sozinho — sem addActionListener(...), o clique é ignorado e o programa não dá erro nenhum, simplesmente não reage. Um botão sem listener compila e roda.

Menus — JMenuBar, JMenu, JMenuItem tema do 02 | 07

A hierarquia é fixa e cai em questão de ordenação:

JFrame → JMenuBar → JMenu → JMenuItem

JMenuBar barra = new JMenuBar();
JMenu menuCadastro = new JMenu("Cadastro");
JMenuItem itemCliente = new JMenuItem("Cliente");

menuCadastro.add(itemCliente);
barra.add(menuCadastro);
setJMenuBar(barra);   // método do JFrame — NÃO é add()
Atenção A barra de menu entra com setJMenuBar(barra), não com add(barra). Se usar add(), ela vira um componente comum no meio da janela.

Caixas de diálogo — JOptionPane tema do 02 | 09

MétodoServe paraDevolve
showMessageDialogAvisar alguma coisavoid — não devolve nada
showInputDialogPedir um dado digitadoString (ou null se cancelar)
showConfirmDialogPerguntar Sim / Nãoint — JOptionPane.YES_OPTION vale 0
Duas armadilhas de tipo
  • showInputDialog devolve String, mesmo que a pessoa digite número. Para usar como número é preciso Integer.parseInt(texto) — e isso pode lançar NumberFormatException.
  • showConfirmDialog devolve int, não boolean. Comparar com true nem compila; o certo é if (resp == JOptionPane.YES_OPTION).

JavaFX — o que cai temas 02 | 10 a 02 | 14

A analogia oficial é de teatro, e a prova costuma cobrar justamente essa hierarquia:

ElementoÉ o quêEquivalente no Swing
StageO palco — a janelaJFrame
SceneA cena — o conteúdo exibido no palcoO ContentPane
NodeCada ator — botão, campo, imagemOs componentes J...
public class App extends Application {
    public void start(Stage palco) {          // método obrigatório
        Button botao = new Button("Clique");
        botao.setOnAction(e -> System.out.println("Oi"));
        Scene cena = new Scene(new StackPane(botao), 300, 200);
        palco.setScene(cena);
        palco.show();
    }
}
ConceitoSwingJavaFX
Evento de cliqueaddActionListenersetOnAction

A resposta que a prova quer sobre FXML O FXML descreve a estrutura da interface; o Controller (classe Java) concentra a lógica; o CSS concentra a aparência. A ligação entre eles é feita com fx:controller no FXML e com a anotação @FXML nos campos da classe. É a mesma ideia de separação que o Angular cobra com templateUrl / classe / styleUrl — repare que os dois blocos da prova cobram o mesmo princípio.

Validação de formulários tema do 02 | 14

if (campoNome.getText().trim().isEmpty()) {
    JOptionPane.showMessageDialog(null, "Informe o nome",
            "Erro", JOptionPane.ERROR_MESSAGE);
    campoNome.requestFocus();   // devolve o cursor ao campo
    return;                      // interrompe: não salva
}
try {
    int idade = Integer.parseInt(campoIdade.getText());
} catch (NumberFormatException ex) {
    JOptionPane.showMessageDialog(null, "Idade deve ser um número");
}
Boas práticas que viram alternativa correta Validar antes de gravar; usar trim() para não aceitar só espaços; tratar a conversão com try/catch; dar mensagem específica dizendo qual campo está errado; e devolver o foco para o campo com problema.

2POO que cai junto caiu no ED1

As questões 24 a 30 do ED1 foram todas de POO. Como o ED2 é GUI, o mais provável é que ela volte aplicada à interface. Revisão do essencial:

PilarDefinição que a devolutiva usouNa interface gráfica
EncapsulamentoProtege o estado interno e dá acesso controlado por métodosAtributos private na classe da janela, com get/set
HerançaClasse especializada reutiliza características de outraclass Janela extends JFrame
PolimorfismoMesma operação, comportamentos diferentes conforme o objetoVários listeners implementando actionPerformed de jeitos diferentes
AbstraçãoRepresenta só o que é relevante, ocultando o restoVocê usa JButton sem saber como ele é desenhado
As três confusões que a devolutiva do ED1 corrigiu
  • get/set não garante encapsulamento. Se o atributo for public, o acesso direto continua liberado — animal.nome = "Rex" funciona. O encapsulamento vem do private, não da existência dos métodos.
  • Sobrecarga ≠ sobrescrita. Sobrecarga (overload) é o mesmo nome com parâmetros diferentes, na mesma classe. Sobrescrita (override) é a subclasse redefinindo um método herdado, mantendo a assinatura.
  • Atributo semelhante não justifica herança. Herança precisa de uma relação real de especialização ("é um tipo de"), não só de campos parecidos.
Interface Uma classe usa implements para assumir o contrato de uma interface, e extends para herdar de uma classe. ActionListener é exatamente isso: uma interface que obriga sua classe a ter o método actionPerformed. Classe abstrata não pode ser instanciada diretamente.

5Cola de 1 minuto

  • EXIT_ON_CLOSE senão só esconde
  • JFrame = BorderLayout · JPanel = FlowLayout
  • Radio exclusivo → ButtonGroup
  • Rolagem → JScrollPane
  • setJMenuBar(), não add()
  • Sem addActionListener → clique ignorado

JOptionPane

  • Message → void
  • Input → String (ou null)
  • Confirm → int (YES_OPTION)

JavaFX

  • Stage → Scene → Node
  • setOnAction no lugar do listener
  • FXML = estrutura · CSS = estilo · Controller = lógica

Angular

  • {{ }} interpolação
  • [ ] property · ( ) event
  • Standalone → recurso vai nos imports
  • ! não verifica nada em execução

BD II e Grafos

  • IS NULL, nunca = NULL
  • NOT NULL em tabela cheia → 3 passos
  • BETWEEN é inclusivo
  • Soma dos graus = 2 × arestas
  • Diagonal ≠ 0 → laço → não é simples
  • Maior grau = hub, não ponto fraco
Último conselho Nas questões de "ache o erro", procure primeiro o que falta — o listener não registrado, o WHERE ausente, o ButtonGroup esquecido, o módulo fora dos imports. Nas quatro devolutivas, o erro quase nunca foi algo escrito errado: foi algo não escrito.
